# Security Secrets Rotation Schedule

**Last Updated:** 2026-06-07

This document tracks the rotation of critical security secrets. Rotate every 90 days.

## Critical Secrets (Rotate Every 90 Days)

### 1. Firebase API Key
- **Type:** Public Firebase Client SDK key
- **Location:** `NEXT_PUBLIC_FIREBASE_API_KEY` in `.env.production`
- **How to Rotate:**
  1. Go to Firebase Console > Project Settings > General tab
  2. Create a new Web API key (Web app section)
  3. Copy the new key to `.env.production` and update in Vercel secrets
  4. Wait 24 hours for DNS propagation
  5. Revoke old key in Firebase Console
  6. Redeploy: `vercel --prod`
- **Last Rotated:** [DATE]
- **Next Rotation Due:** [DATE + 90 DAYS]

### 2. MORALI_PIN_MASTER_KEY
- **Type:** AES-256 encryption key for PINs
- **Location:** `.env.production` (server-side only)
- **Risk:** High - Used to decrypt all stored PINs
- **How to Rotate:**
  1. Generate new key: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
  2. Create migration script to re-encrypt all PINs with new key
  3. Update `.env.production` and Vercel secrets
  4. Run migration: `npm run migrate:pin-key`
  5. Verify all PINs still decrypt correctly
  6. Revoke old key from documentation
  7. Redeploy
- **Last Rotated:** [DATE]
- **Next Rotation Due:** [DATE + 90 DAYS]

  6. Redeploy
- **Last Rotated:** [DATE]
- **Next Rotation Due:** [DATE + 90 DAYS]

  4. Document new password in secure location (1Password, Vault)

### 9. Firebase Service Account Private Key
- **Type:** Admin SDK authentication (GCP service account)
- **Location:** `FIREBASE_SERVICE_ACCOUNT_JSON` (server-side only, CRITICAL)
- **Risk:** CRITICAL - Full database access if compromised
- **How to Rotate:**

  2. Click "Generate New Private Key"
  3. Download new service account JSON
  4. Extract key content: `cat service-account-key.json | jq -c . | tr -d '\n'`
  5. Update `FIREBASE_SERVICE_ACCOUNT_JSON` environment variable
  6. Update in Vercel secrets (make sure to use the JSON string, not file)
  7. Delete old service account key from GCP console
  8. Monitor Firebase Admin SDK logs
  9. Redeploy

## Monthly Security Audit

- [ ] Check for exposed secrets in Git history: `git log -p --all -S 'secret' | head -100`
- [ ] Verify all `.env.production` variables are set in Vercel
- [ ] Check Sentry for unexpected errors or security warnings
- [ ] Review Firebase security rules for unintended access
- [ ] Audit admin activity logs

## Emergency Rotation (If Compromised)

1. **Immediately:**
   - Remove compromised secret from code and environment
   - Revoke old secret at provider
   - Update all references to use new secret

2. **Within 1 hour:**
   - Redeploy application
   - Monitor logs for suspicious activity
   - Notify security team

3. **Within 24 hours:**
   - Review audit logs for unauthorized access
   - Reset affected user credentials
   - Post-mortem analysis
